# 3회차 요구사항 정의서

## 1. 서비스 정의

기존 FR-E800 매뉴얼 RAG를 `FR-E800 정비 플래너`로 확장한다. 사용자는 알람 코드나 증상과 함께 날짜, 지역, 시간대, 강수, 공휴일 조건을 입력한다. 서비스는 제조사 보수편 근거와 외부 일정 정보를 서로 섞지 않고 조회한 뒤, 조건을 확인할 수 있는 범위에서만 정비 날짜를 제안한다.

- 진단·점검·대처 근거: 기존 FR-E800 보수편 RAG만 사용한다.
- 위치·날씨·공휴일: 사용자가 명시한 일정 조건을 확인하는 데만 사용한다.
- 매뉴얼에 없는 작업 시간, 고장 원인, 점검 항목 간 연결은 만들지 않는다.
- 작업 시간이 없으면 시작·종료 시각을 만들지 않고 저장 전에 되묻는다.
- 건강·금융 도메인이 아니므로 전문가 면책 문구 대상은 아니다. 실제 설비 작업은 현장 안전 절차와 제조사 매뉴얼을 따라야 한다.

## 2. 도메인 선택 조건

### 외부 API 3종

| API | 제공 정보 | 사용 시점 | 인증·이용 조건 |
|---|---|---|---|
| [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api) | 지역명 후보, 위·경도, 행정구역, 시간대 | 날씨 조건이 있는데 좌표가 없을 때 | 비상업 무료 API는 키가 필요 없다. GeoNames 기반 위치 데이터 출처를 표시한다. Open-Meteo 무료 API 약관과 CC BY 4.0 표시 조건을 따른다. |
| [MET Norway Locationforecast 2.0](https://api.met.no/weatherapi/locationforecast/2.0/documentation) | 좌표별 9일 예보, 강수량, 기온, 풍속, 기상 코드 | 사용자가 강수 조건을 지정했을 때 | 식별 가능한 User-Agent가 필수다. 좌표는 소수 4자리로 제한하고, 비북유럽 동일 요청은 3시간보다 자주 반복하지 않으며 전체 20 req/s 미만을 지킨다. CC BY 4.0 출처를 표시한다. 운영 전 책임자가 [이용 약관](https://api.met.no/doc/TermsOfService)을 직접 검토해야 한다. |
| [Nager.Date Community REST API v4](https://github.com/nager/Nager.Date/blob/main/doc/examples/rest-api.md) | 국가·연도별 공휴일과 적용 범위 | 사용자가 공휴일 제외를 명시했을 때 | 호스팅 REST API는 키 없이 사용한다. v3는 2027-01-31 지원 종료 예정이므로 v4 경로를 사용한다. 공식 문서에 고정 호출 한도가 명시되지 않아 응답 캐시와 서비스 정책 변화를 운영 단계에서 확인한다. |

Open-Meteo Forecast API는 2026-11-18 개발 환경에서 15초 읽기 시간 초과와 27.6초 후 연결 재설정을 실제로 확인했으므로 구현 대상에서 제외했다. 대신 실제 200 응답을 확인한 MET Norway Locationforecast를 사용한다.

### 판단이 필요한 대표 요청

1. `E.OC1 점검 근거와 다음 주 수원시, 경기도에서 비 없는 평일 오전 공휴일 제외 정비 계획을 세워줘.`
2. `E.THT 원인과 2026-11-25 오전 정비 계획을 알려줘.`
3. `같은 조건에서 비 조건은 빼고 다시 계획해줘.`

LLM이나 규칙만으로 외부 결과 없이 답하면 지역 동명이인, 실제 예보, 공휴일 여부를 임의로 정하게 된다. 서비스는 각 값을 Tool로 확인하며 확인 실패 값은 채우지 않는다.

### 저장 결과물

정비 계획은 제목, 알람 코드, 장소, 날짜, 시작·종료 시각, 메모, 생성·수정 시각을 저장한다. 같은 날짜의 시간이 겹쳐도 저장하되 겹치는 계획 목록을 함께 반환한다. 실행 로그는 별도 SQLite DB에 세션 단위로 저장하며 조회·삭제만 허용한다.

## 3. 사용자 시나리오

| 구분 | 요청 | 기대 동작 |
|---|---|---|
| 한 번에 충족 | `2026-11-25 오전 정비 계획` | 외부 조건이 없으므로 Tool 없이 날짜 후보를 제시한다. 시간은 만들지 않는다. |
| 재계획 | `다음 주 수원시, 경기도에서 비 없는 평일 오전 공휴일 제외 정비 계획` | 위치→예보→공휴일을 호출한다. 첫 날짜에 강수가 있으면 기존 Tool 결과를 재사용해 다음 날짜를 판단한다. |
| 상한 도달 | 모든 후보 날짜에 강수가 있는 테스트 예보 | 최대 재계획 횟수에 도달하면 중단 이유와 제외 날짜를 반환한다. |
| Tool 실패 | 날씨 API 시간 초과 | `TIMEOUT`을 기록하고 확인하지 못한 강수 조건을 충족으로 처리하지 않는다. |
| Tool 불필요 | `안녕하세요` | Tool을 호출하지 않고 사용 범위를 안내한다. |
| 조건 부족 | `비 없는 날 정비 계획 세워줘` | 날씨 Tool 호출 전에 지역과 날짜를 되묻는다. |
| 후속 요청 | `같은 조건에서 비 조건은 빼줘` | 세션 메모리에서 날짜·지역을 유지하고 강수 조건만 해제한다. |

## 5. 비기능 요구사항

- API 키와 원격 오류 본문을 응답·로그에 남기지 않는다.
- 외부 Tool은 예외를 밖으로 던지지 않고 공통 실패 응답으로 변환한다.
- 재계획 기본 상한은 3회다.
- FastAPI, Agent, Tool, 저장소, 프론트엔드를 파일 단위로 분리한다.
- 매뉴얼 DB, Vector DB, 원본 PDF, `.env`, 모델 파일은 Git과 ZIP에서 제외한다.
- MET Norway와 Open-Meteo 데이터는 화면에 출처를 표시한다.
