# 채팅방과 대화 맥락 검증

실행: 2026-10-27, 실제 LLM·UI 검증 완료 시각 21:57 KST.

## 구현 범위

- 왼쪽에서 새 채팅방 생성, 첫 질문으로 제목 지정, 이전 방 선택.
- 별도 SQLite `storage/chats.db`에 방·메시지·응답 시간·맥락 저장. 매뉴얼 DB·Chroma 인덱스 재사용.
- 같은 방의 알람 코드·증상과 최근 후속 조건을 현재 질문에 연결. 다른 방의 대화는 전달하지 않음.
- 새 코드·새 증상 우선, 여러 코드 중 대상이 모호하면 확인 요청. 이전 생성 답변은 기술적 근거로 사용하지 않음.
- 증상 후속 검색은 원래 증상 질의로 순위를 유지하고, LLM은 현재 질문과 이전 사용자 조건을 참고함. 실제 토큰 예산·원문·필수 목록·출처 검증 유지.

## 자동 회귀 검사

`python -m pytest -q --junitxml=logs/chat-context-tests.xml`: **133개 통과**, 실패·오류·건너뜀 0, 23.57초.

여기에는 모의 HTTP/LLM 테스트와 로컬 PDF·DB·E5/Chroma를 이용한 검사, Streamlit AppTest가 포함됩니다. pytest 통과 수를 실제 LLM 생성 성공 수로 해석하지 않습니다.

새 검사는 방별 저장·격리·재열기, SQL 문자열의 데이터 처리, 맥락 이어받기, 코드 전환·모호한 대상·이전 알람 재선택, 문맥 길이 제한, 기존 평가 질의 보존, UI 전환·복원·기존 세션 이관·서버 오류 유지, 매뉴얼 DB 경로 보호를 포함합니다.

기존 40문항을 **LLM 없이** 1회씩 다시 평가했습니다. 성공 40회·실패 0회, **Hit@3 90% (9/10)**로 기존 수치를 유지했습니다. 코드 없는 증상 질문 5개는 Hit@3에서 제외합니다. [검색 회귀 상세](local_llm/chat_regression/REPORT.md)

## 실제 검색과 원본 보존

`모터 시동이 걸리지 않아` → `그럼 점검 순서는?`를 실제 E5·Chroma와 **evidence_only**로 검사했습니다. 맥락 반영·원문 검증을 통과하고 원래 검색 결과 ID와 순서가 일치했습니다. 이 두 요청에는 LLM을 호출하지 않았습니다.

실제 검증은 `tmp/chat-validation/`의 별도 채팅 DB를 사용했습니다. 기존 `storage/alarms.db`, `storage/chroma/manifest.json`, `evaluation/REPORT.md`의 전후 SHA-256이 일치했습니다. 재색인이나 기존 데이터 삭제는 수행하지 않았습니다. 상세 실행 결과는 Git에서 제외된 `logs/chat-context-smoke.json`과 JUnit에 보존했습니다.

## 남은 한계

- 맥락 연결은 규칙 기반입니다. 대상이 불명확한 표현은 코드·증상을 다시 확인해야 합니다. 사용자 질문 전체 기록은 저장하지만 모델에는 대상과 최근 조건만 제한된 길이로 전달합니다.
